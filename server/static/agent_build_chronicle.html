00The arena

Sea of Colours is a two-player, hidden-information resource game on a 40×28 grid.

Each night an agent launches probes (which reveal a Euclidean radius-4 disk of fog), drops harvesters that walk chains of cells banking RED (score), BLUE (weapons fuel), and avoiding GREEN (poison). By day it runs an orbit economy — build probes/harvesters, refine trace→vein, catapult high-purity parcels for score, and build chaff flares that jam the opponent's action slots during an egress window.

The agent's whole night is one JSON document: a moves array plus its plan, rationale, prediction, and reflection. If that document is truncated or malformed, the turn is wasted. That single constraint is the source of nearly every hard problem below.

01The core problem, stated plainly

The recurring failure

The agent runs out of budget before it emits a complete plan.

Across every version, the same thing kept happening: the model would think, narrate, deliberate — and hit its cap mid-sentence, before the moves array was ever written. A truncated turn is a dead turn. In a 7-night season, two dead turns loses the game.

The naïve reactions all failed:

✗ tried

"Be concise"

The model still front-loads reasoning prose and runs out. Politeness is not a budget.

✗ tried

Bigger cap

Extended thinking expands to fill any budget. A bigger cap buys a longer ramble, not a finished plan.

✗ tried

"Don't think"

v6's "reason in your head" fix. It works — but you get a fast, obedient collator of deterministic hints, not a strategist. Useful, still dumb.

✓ worked

Separate the budgets

Thinking and answering must be different, individually-capped resources. This is Finding 1 — and it was an API problem all along.

03Finding 1 — the token-opaque budget HUGE

It was never the model. It was the API surface we were calling — and specifically which controls that surface exposes over how the token budget is spent.

Snowflake Cortex exposes two different ways to talk to the same underlying model, and they have fundamentally different budget mechanics. We built v1–v6 on the wrong one for our task.

Why it didn't work — the exact mechanism

On the Agents API the model's response arrives as a Server-Sent Event stream of typed events. Reasoning tokens come on their own event type (response.thinking.delta / response.thinking); answer tokens come on separate text frames; tool calls interleave. The server-side orchestration loop decides, on its own, how many tokens to spend thinking before it emits a single answer token — and that decision is not a parameter you can set.

So the only lever the client actually has is a guillotine: keep reading the stream until a wallclock deadline, then close the socket. Our real invoker does exactly that (agent/cortex_invoker.py):

for line in response.iter_lines():           # SSE frames, in arrival order
    if time.time() - started >= wallclock_cap_s:
        wallclock_capped = True
        break                                # <-- the ONLY budget control: cut the wire

    if current_event.startswith("response.thinking"):
        thinking_response += tok            # divert reasoning to a side buffer (OUR isolation)
        continue                            # ...but the SERVER already spent the time/tokens
    agent_response += tok                    # the answer — may never arrive before the cut

We can isolate the thinking tokens on our side (so they don't corrupt the answer buffer), but we cannot stop the server from spending the turn on them. Measured for haiku-4-5 with a reasoning-inviting prompt: ~27 KB / ~30–44 s of thinking arrives before the first answer token. That makes the guillotine a lose-lose:

cut early

Cut at 18s

You slice through the thinking stream. No answer frame ever arrived → empty/partial plan → fallback. (This is precisely why the v7 two-call thinker returned [thinker=none] 7/7 nights.)

cut late

Cut at 50s

The think finishes, but you've blown the turn's wallclock and the answer is rushed in whatever's left — often still truncated, and always slow.

There is no cut point that reliably yields "a bounded think and a complete answer," because the think:answer split is decided server-side and ordered think-first. The budget is "opaque" in the literal sense: you cannot see or set how it is divided.

v6's "reason in your head" trick is the only other Agents-API setting available — it instructs the model to skip extended thinking, so the loop jumps straight to the answer: fast and complete, but you've thrown away reasoning entirely and get a collator of our precomputed hints, not a strategist. On the Agents API there is no middle setting. That binary — runaway think or no think — is the whole trap.

Why it does work now — the exact mechanism

The inference /chat/completions API is a plain request/response with no orchestration loop, and it exposes the budget as three independent, server-honored controls:

Put together: the answer can never be starved by the think (different pools), the answer can never be sliced mid-structure (the model self-budgets to the ceiling), and even a minimal answer is a valid plan (constrained decoding). The whole client is ~150 lines, non-streaming because the call is now bounded (orchestrator_2/cortex_chat.py):

payload = {
    "model": "claude-haiku-4-5",
    "messages": [{"role": "user", "content": prompt}],
    "max_completion_tokens": max_tokens,   # dial 1: HARD answer budget
    "response_format": response_format,    # dial 3: grammar-enforced shape
    # "reasoning": {"max_tokens": 1500},      # dial 2: bounded think (sonnet/opus)
    "stream": False,
}
resp = requests.post(endpoint, headers=auth, json=payload, timeout=wallclock_cap_s)
choice = resp.json()["choices"][0]
return {
    "response":  choice["message"]["content"],            # the complete plan
    "thinking":  choice["message"].get("reasoning_content"), # isolated, audit-only
    "capped":    choice["finish_reason"] == "length",     # real truncation signal
}
The one-sentence difference

The Agents API gives you one knob — a wallclock guillotine — over a think+answer budget the server divides; the inference API gives you three knobs — a hard answer budget, a separate think budget, and an enforced output grammar — that you divide. Reliable completion was never a prompting problem; it was a matter of calling the surface that exposes the budget you need to control.

Making this knowledge universal at Snowflake

This isn't a tabula quirk — it's a decision rule for any token-bounded agent on Cortex. The portable playbook:

  1. Pick the surface by task shape, not by habit. If the deliverable is a complete, well-formed answer (a plan, a JSON payload, a classification, a structured extraction), use the inference API. Reserve the Agents API for genuinely autonomous, multi-step tool-looping work where you actually want the server to orchestrate and can tolerate variable-length runs.
  2. Always set max_completion_tokens and treat finish_reason == "length" as your authoritative truncation signal. Never infer truncation from string heuristics.
  3. Budget thinking explicitly with reasoning.max_tokens (or effort) on a thinking-capable model — never let reasoning and answer share a pool. Remember temperature=1 is required when reasoning is on.
  4. Enforce output shape with response_format: json_schema (constrained decoding), not prose. Design around Cortex's strict-mode quirks: no type-arrays (no nullable-via-union), no minItems/maxItems, set additionalProperties:false, and keep only always-present fields in required.
  5. Keep deterministic work out of the token budget. Precompute everything that isn't a genuine judgment call (arithmetic, legal-move sets, candidate lists) and hand it in; spend the model's bounded budget only on the irreducible decision.
  6. Ship it as one shared client with a stable envelope. CortexChatInvoker returns the same {response, thinking, capped, wallclock_capped, elapsed_ms} shape as the Agents client, so any team can switch transports without touching downstream code. That envelope compatibility is what makes the fix a library, not a one-off.

In short: standardize on "hard answer budget + separate think budget + enforced grammar" as the default contract for every Cortex agent that must return a complete answer. The opaque single-budget path should be the exception you opt into for tool-looping, not the default you back into.

04Finding 2 — the forced moves-first contract HUGE

Make emitting the complete answer the first, cheapest, most-protected thing the model does — then let the API guarantee its shape and a deterministic pass guarantee its legality.

Moves-first began (v5) as a pure truncation defense: put moves first in the output so that if the model is cut off, the valuable part is already written. On the inference path it fuses with constrained decoding into something stronger — a layered contract where something legal always ships:

  1. Order: moves is the first field emitted. Focuses the model on committing actions before prose, and preserves the payload under any early stop.
  2. Precomputed hints: ready-to-copy chains, comb paths, and supersede targets arrive as compact lines — the model selects, it doesn't derive from scratch.
  3. Schema guarantee (v7): response_format: json_schema makes a well-formed moves object valid by construction — enforced by the decoder, not requested in prose.
  4. Move sanitizer: a deterministic pass repairs game-illegal moves (out-of-bounds, non-adjacent steps, self-crush, orphaned chains) before submission.
  5. Finisher: on the Agents path, if JSON still truncates, a tiny second call completes it from the board state. (On the inference path this rarely fires — the cap + self-budgeting prevent the truncation.)
  6. Heuristic net: if everything above fails, a deterministic policy plays the turn — a dead turn becomes a decent turn.

Shape ≠ legality — why the schema alone isn't enough

This is the subtle part builders miss. Constrained decoding guarantees the output is a syntactically valid object of the right types. It cannot express the game's legality rules — those aren't a grammar:

  • a step must be Manhattan-1 from the harvester's current cell (a runtime fact the schema can't see);
  • moves must follow the drop → step* → pickup grammar per unit;
  • a drop must not crush your own live probe.

So {"a":"step","unit":"harvester_p1","to":[30,2]} is schema-valid and game-illegal if the harvester is at (10,10). That is exactly why the two guarantees are kept deliberately separate: the schema owns shape (the object exists and is parseable), the sanitizer + engine own legality (the moves are playable). Collapsing them into one layer is the trap — you'd either over-constrain the schema (and hit Cortex strict-mode rejections) or trust the model to self-enforce runtime rules (which it doesn't).

Does the schema fight moves-first? No — they reinforce

A fair worry: constrained decoding fixes the emission order to the schema's property order, so does it override our moves-first discipline? In practice they compose. We put moves at the front of the schema's properties, so the decoder emits it first anyway. And the truncation-safety reason for ordering largely dissolves on this path — the whole object is guaranteed complete (finish_reason tells you), so ordering is no longer load-bearing for completeness. It survives as a focusing device (commit actions, then explain) and as defense-in-depth for the Agents path. Ordering + schema = belt and braces, not a conflict.

Designing the schema for Cortex strict mode

Cortex's strict json-schema mode rejects several common constructs; the schema is shaped around them empirically:

Cortex rejectsConsequence for us
type: ["object","null"]
(nullable via union)		can't make a field "object-or-null" → we make optional things optional (absent), not nullable. (This is why reflection_on_last_night is omitted on night 1 rather than sent as null.)
minItems / maxItemscan't force "≥1 move" at the schema level → the sanitizer + heuristic net own the empty-moves case instead.
heterogeneous array itemsfine — as long as only the always-present field is required and the rest are optional.

Hence the move item requires only a (the action); unit/at/to are optional so one schema covers all four verbs, and the sanitizer fills/repairs the rest:

# chat_schema.py — one loose item type covers drop/step/pickup/probe.
_MOVE_ITEM = {
  "type": "object", "additionalProperties": False,
  "properties": {
    "a": {"type": "string", "enum": ["drop","step","pickup","probe"]},
    "unit": {"type": "string"}, "at": _CELL, "to": _CELL,
  },
  "required": ["a"],          # shape only; legality is the sanitizer's job
}
The contract, in one line

The API guarantees the answer exists and parses; the sanitizer + engine guarantee it's playable; the heuristic net guarantees a turn ships regardless. Never make one layer do another's job.

05What v6 actually changed comprehension

v6 kept the moves-first win and added three understanding upgrades. (Full detail: harnesses/CHANGES_TABULA_v6_v7.md.)

Grounded reflection

v5 authored its "what happened last night" from memory and routinely got it wrong. v6 feeds the engine-resolved truth — actual banked points and concrete losses (chaff jam, probe crush, dawn crash) — and the schema forces the agent to echo the exact number and name the gap cause. It can no longer invent an outcome.

Fog-gated hot-drops with a precomputed comb path

A "hot drop" only makes sense if the target is genuinely fogged. v6 gates on that (target_in_fog) and precomputes a blind serpentine comb over the probe's radius-4 disk — staying in-disk, avoiding known green, biased toward value — so a hot-drop becomes a ready-to-copy chain instead of a 2-step gesture.

Absorb-first-step (anti self-crush)

Dropping a harvester onto your own live probe crushes it. When a harvest chain follows, v6's sanitizer absorbs the first step into the drop — rerouting the drop to the first step's cell — sparing the probe and keeping the chain intact.

06What v7 actually changed containment

✗ parked

Two-call reasoning split

A dedicated thinker commits a tiny DECISION directive; the mover executes it. Fully built + tested, kept behind TABULA_V7_MODE=split. Parked as a negative result: haiku thinks unbounded on the Agents API, so an 18s cap truncated the thinker every night and a 50s cap broke the wall while landing a directive only ~2/7 nights — with a score regression (980 vs 1768).

✓ shipped

Inference-API mover

The containment fix from Finding 1: CortexChatInvoker + MOVES_RESPONSE_FORMAT, wired behind TABULA_V7_MOVER_API=chat. Hard answer cap, separate think channel, schema-guaranteed moves. This is the winning path.

The failed split matters: it's the experiment that isolated the root cause. Watching the thinker overrun its budget on the Agents API is what proved the problem was the opaque budget, not the model — which pointed directly at the inference API as the cure.

09Where it's still dumb (the honest part)

A complete plan is not a smart plan. The same three failures recur across all seeds.

1 · Chaff blindness → dawn crashes

The heuristic builds a chaff flare and fires it during an egress window, cancelling the agent's action slots. In every seed the agent kept scheduling its pickup inside that window, got jammed, and lost a loaded harvester to Aurora destruction at dawn — even after being chaffed the night before.

2 · The reflection channel was missing on the winning path now fixed

Root cause of #1 — diagnosed, then fixed

The inference schema (chat_schema.py) originally omitted reflection_on_last_night — so in strict json-schema mode the field was silently dropped and v6's grounded-reflection ("you got chaffed, move your egress") never reached the model on the chat path. The whole pipeline behind it still ran (the recorder fills the real numbers; the prompt injects the REFLECT block) — only the schema declaration was missing, severing the night-to-night learning loop. Fix shipped: the field is now in the schema (optional, so night 1 can omit; live-verified the model emits a correct grounded reflection). Honest caveat: this restores the capability; it is not yet proven to change chaff behavior — that needs a controlled test against a chaff-building opponent.

3 · Unit-id / pickup confusion

On one final night the agent scheduled steps and a pickup on harvester_p1_2 (which was "not on surface" / "already orbital") while the real loaded harvester never got picked up — compounding the chaff loss.

seed 2024, day 7
[ERR] p1: step harvester_p1_2 → (14,20) — not on surface
[ERR] p1: pickup harvester_p1_2 — already orbital
... meanwhile harvester_p1 (loaded) is never picked up → crashes.

Notably, the agent still won every game: its RED-chain combing + supersede doctrine starved the opponent of RED (p2 stranded at 16–134 points). But these gaps are exactly the ceiling that the v8 worldview restructure (complete the picture) and then bounded native thinking (v9, add depth) — on top of the now-restored reflection loop — are meant to break.

10v8 shipped the worldview — v9 is the bet on native thinking

What v8 actually shipped

Before making the agent think harder, we checked whether it was even being told what happened to it — and it wasn't. v8 became the worldview release: a 3-pillar prompt restructure, the collision blind-spot fix (the agent recited the collision rule on day 7 and dove onto the mutual-kill cell anyway, because on the nights it collided it was never told), plus enemy-probe / weapon-geometry blocks and a redsign-poker doctrine. It won the seed-42 three-way. Read the full v8 story →

v7 proved containment; v8 fixed what the agent knows. v9 asks the next question: now that the answer is safe and the picture is complete, can we spend a bounded, real think to make the answer smarter — without reopening the runaway wound?

v7's mover is still haiku, which has no native thinking on this API — it answers within the cap, competently, but it doesn't reason. The gaps in §09 (chaff pre-emption, unit-identity discipline, multi-night planning) are depth problems, and depth is what a thinking-capable model buys. v9 (planned) switches the mover to claude-sonnet-4-6 and turns on the second dial from Finding 1:

payload = {
    "model": "claude-sonnet-4-6",        # thinking-capable (haiku is not)
    "messages": [...],
    "reasoning": {"max_tokens": 4000},    # dial 2: a BOUNDED real think
    "max_completion_tokens": M,           # dial 1: answer budget, untouched by the think
    "response_format": MOVES_RESPONSE_FORMAT,  # dial 3: shape still guaranteed
    "temperature": 1,                      # required whenever reasoning is on
}

The critical difference from the parked v7 two-call split: there, the "think" was unbounded (haiku on the Agents API, ~40s, no way to cap it). Here it is a hard sub-budget on a separate channel — the exact mechanism that made the answer safe now makes the think safe. We already measured that sonnet honors it: latency scales monotonically with the budget (1500→~16s, 4000→~25s), and the answer budget is never touched.

What actually changes vs v7 (and what doesn't)

Changes

Mover model → sonnet-4-6; add a bounded reasoning.max_tokens pass; the isolated thinking trace gets persisted to SOC_AGENT_INVOCATION for audit; instructions move inline as a system message (no server-side agent spec, since tabula uses no tools).

Stays identical

Everything harness-side: the v8 worldview prompt, precomputed hints, grounded reflection, the move sanitizer, the finisher, the heuristic net, and the json-schema shape guarantee. v9 is a transport + model swap behind the same envelope — not a rewrite.

Why it's a bet, not a slam-dunk

Native thinking is slower and pricier per token, so it has to earn its place. v9 ships only if it clears explicit gates:

  • Quality is the whole point: the reasoning trace must show genuine chaff anticipation / targeting logic that demonstrably changes the moves — not post-hoc rationalization of what haiku would have done anyway.
  • Wallclock: sonnet + think must fit the accepted ceiling (55s, or a deliberately raised one justified by the quality gain). Bounded via reasoning.max_tokens + effort.
  • Cost: quantified per season; only worth it if quality clearly wins.
  • It must beat both v7 and v8 on the full seed set (42 / 7 / 99 / 2024) in a three-way A/B — else v8 stays champion and v9 is shelved with its findings recorded, exactly like the two-call split.

The elegance is that v9 needs no new invention — it's Finding 1's three dials, with dial 2 finally turned up on a model that can use it. Containment made the answer trustworthy; the v8 worldview made the picture complete; only because of both can we now safely add depth.

11What we'd tell the next builder

Separate the budgets, at the API

Answer tokens, think tokens, and output shape must be three independent guarantees. A single opaque budget is the root of "it never finished."

Make the answer the cheapest act

Moves-first + schema-enforced shape means something legal always ships. Protect the deliverable structurally, not with polite instructions.

Precompute the deterministic, reserve tokens for the strategic

Hand the model ready chains, comb paths, supersede targets. Don't spend its budget re-deriving arithmetic.

Keep the learning loop in the schema

A field you drop from the schema is a capability you delete. The chaff blindness is a missing reflection field, nothing more.

Negative results are load-bearing

The parked two-call split is what isolated the opaque-budget root cause. Keep failed experiments behind a flag as evidence.

A complete plan ≠ a smart plan

Containment gets strategy to the board reliably; the v8 worldview makes sure the strategy is reasoning about the truth. Depth (anticipating chaff, managing unit identity) is the next mountain — v9.

"An agent — haiku or anyone — needs to be able to provide an answer in 15s, 30s, 60s, or whatever token limit, and not twist its thinking. We needed a cohesive, contained way of extracting raw thinking from the model over this strategic surface." — the brief that drove Finding 1.
