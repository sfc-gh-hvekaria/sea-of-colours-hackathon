# Probe echo bug — debug notes (2026-06-23)

## Symptom
After EMP hits opponent probes, their `via="probe_launch"` fog+glyph markers persist
in the map view. Belt-and-suspenders renderer check did not suppress them.

## What should happen
`_emp_sweep_destroy` (session.py:6464) calls `_clear_probe_launch_markers(eid, x, y)`
which deletes the marker from every `probe_intel` bucket for that cell.
Additionally, the renderer check at line ~2278 should show fog if the probe_id is
no longer in `self.entities`.

## Possible causes to verify tomorrow

### 1. Server did not reload with the fix
The dev server may have been serving the old code. Verify with a hard restart.

### 2. probe_id type mismatch or entity key mismatch
`_clear_probe_launch_markers` checks `entry.get("probe_id") == probe_id`.
`probe_id` passed in is `eid` (the entities dict key, a string like "probe_p2_1").
The stored `probe_id` in the marker was set during `_pulse_probe_launch`.
Add `print(f"DEBUG clearing {probe_id} at {x},{y}, found={entry.get('probe_id')}")` in
`_clear_probe_launch_markers` to verify they match.

### 3. EMP cells set does not contain the probe's position
`_emp_sweep_destroy` checks `(int(en.x), int(en.y)) in cells`.
`cells` is a set of (int, int) tuples from `_manhattan_disk`.
Add `print(f"DEBUG emp sweep: probe {eid} at ({int(en.x)},{int(en.y)}), in_cells={...in cells}")`.

### 4. Belt-and-suspenders check: _pid is None
If `snap.get("probe_id")` returns None AND no occupants have type=="probe", `_pid` is None
and the check is bypassed. Check by printing what snap contains for the affected cell.

### 5. probe still in self.entities when live map is rendered
The EMP fires during the night. After the night the probe should be gone.
But the live map payload might be cached from a pre-EMP state.

## Quickest diagnostic
Add to `_generate_dense_cells_for_player`, inside the `via="probe_launch"` branch,
just before the belt-and-suspenders check:

    print(f"DEBUG probe_launch marker: cell={k} pid={snap.get('probe_id')} in_entities={snap.get('probe_id') in self.entities}")

Run a game, fire EMP, check server logs for DEBUG lines after the EMP night.
